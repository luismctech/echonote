# VBx re-segmentation with a PLDA back-end (T10)

Date: 2026-10-13. Task T10 of `vad-diarization` (branch `feat/vad-diarization`, commits
`64f2794..ab05093`). Eval data, scripts, embeddings and raw results live in the session
scratchpad (`t10/`, `der-eval/`). They are not committed.

## Question

ADR 0001 puts a re-segmenting refine behind `OfflineRefineMode::Resegment`. T9 proved the plan
end to end with entry-level AHC, which over-counted speakers. Does VBx (VB-HMM over
PLDA-projected embeddings, AHC initialisation) beat the merge-only refine on the held-out test
sets by the margin the owner set (Q4)? What do the denser window embeddings that Q3 allows add,
and what does the refine cost at stop?

**Answer:** no, it does not meet Q4, so the default stays `MergeOnly`. VBx fixes the speaker
count (Spanish test: 3.45 estimated speakers against 2.80 true, 10/20 files exact, down from 4.15
and 3/20). It also wins by a wide margin on dev. On test, though, a few files collapse, and the
weighted test DER is 9.31 against 6.73 for merge-only. Dense windows made dev DER worse and cost
about 1.5x the pipeline time, so they are off by default.

## What was built

| Piece | Where | Notes |
|---|---|---|
| Bounded merge-only refine | `offline_refine.rs` (`64f2794`) | For unit vectors, average linkage equals `dot(sum_a, sum_b) / (n_a n_b)`. The pass keeps one sum per speaker and no `n x n` matrix. At the 16 384-entry cap it allocated 1 074 MB before and about 0 MB after (a test counts the allocations). Dev DER is unchanged: 5.85 / 16.26 |
| `bench embed-dump` | `echo-proto` (`190d037`) | Embeds `<wav> <label>` lists with the app's adapter for offline fitting. Developer tooling; the app never writes embeddings |
| PLDA back-end | `plda.rs`, `assets/`, `scripts/fit-plda.py` (`c3f5b85`) | VBx recipe: `l2norm(LDAᵀ l2norm(x - mean1) - mean2)`, then a two-covariance PLDA diagonalised with `eigh(B, W)`. Little-endian file with a magic, version and dimensions. The multilingual CAM++ model (192 -> 128, 166 164 B, SHA-256 `928d73eb…3558`) is compiled into the binary |
| VBx port | `vbx.rs` (`99c9f10`) | `VBx`, `forward_backward` and `twoGMMcalib_lin` from BUTSpeechFIT VBx `57466e6` (Apache-2.0; notice and licence in `third_party/VBx-LICENSE`). The forward-backward uses the rank-one transition structure, `O(T·S)`. Pause/resume epochs are independent runs. Matches the official Python to within 1e-9 |
| VBx reclusterer | `vbx.rs`, `resegment.rs`, `online_diarizer.rs` (`cc02339`) | Embeddings go to the LDA space. AHC over at most 2 048 representatives, cut at the per-recording two-Gaussian threshold plus an offset, seeds at most 20 speakers. VBx relabels every entry, then Hungarian id matching runs as in T9. Without a PLDA model of the right dimension the mode falls back to merge-only |
| Dense windows (Q3) | `embedding_log.rs`, `online_diarizer.rs` (`73741c3`) | 1.5 s windows tile spans longer than 3 s. Only in `Resegment`, and only with `with_dense_windows(true)`. Capped at 16 384 and thinned in O(n). Off by default (see below) |
| Bench | `bench der --vbx --vbx-grid --plda --dense-windows` (`8d69ff8`) | A grid file scores many VBx settings on the same diarized sessions. The main plan keeps the app's 20 s deadline |
| Calibrated preset | `presets.rs` (`ab05093`) | Multilingual CAM++: Fa 0.5, Fb 5, loopP 0.5, init offset +0.15, LDA 128, smoothing 5 |

## Calibration (dev sets only)

Same dev sets and objective as T6b: `mls_es_dev` (20 synthetic Spanish conversations) and
`voxconverse_dev` (12 real recordings), weighted DER `(2·ES + Vox)/3`. The online clustering
preset (0.45 / cap 8) and the pipeline are unchanged. Grids ran with `--vbx-grid`:

1. Coarse grid, 500 settings: init offset {0.10, 0.15, 0.20, 0.25, 0.30} × Fa {0.2-0.6} ×
   Fb {2, 3, 5, 8, 12} × loopP {0.3, 0.5, 0.7, 0.9}. It ran for 2 PLDA models × windows on/off.
2. Fine grid, 186 settings around the best point: offset {0.12-0.22} × Fa {0.45, 0.5, 0.55} ×
   Fb {4-7} × LDA {64, 96, 128}, plus smoothing {3, 7, 10}.

| Setting (weighted dev DER %) | ES dev | Vox dev | Weighted | ES est / true spk | Vox est / true spk |
|---|---|---|---|---|---|
| Merge-only (current default) | 5.85 | 16.26 | 9.32 | 4.75 / 3.45 | 5.42 / 3.67 |
| T9 AHC resegment | 5.94 | 17.59 | 9.82 | 8.55 / 3.45 | 9.33 / 3.67 |
| VBx recipe defaults (Fa 0.3, Fb 17, loopP 0.99, +-0.015) | 7.37 | 38.68 | 17.81 | 3.20 | 1.25 |
| VBx dev minimum (+0.20, Fa 0.5, Fb 5, loopP 0.5) | 3.59 | 13.53 | 6.90 | 3.45 | 3.75 |
| **VBx preset (+0.15, Fa 0.5, Fb 5, loopP 0.5)** | **3.59** | **14.88** | **7.35** | **3.50** (19/20 exact) | **3.83** (5/12) |
| Same, with dense windows | 5.44 | 16.05 | 8.98 | 3.75 | 4.08 |

What the grids show:

- **The init offset is the sensitive axis.** Spanish dev DER stays at 3.5-3.7 for offsets of
  0.10-0.20 and jumps to 5-6.4 at 0.22-0.25. The dev minimum (+0.20) sits 0.02 from that cliff,
  so the preset uses +0.15. That costs 0.45 points on VoxConverse dev only.
- **Fb trades speakers for confusion.** Fb 2-3 over-splits (6.45 estimated speakers at Fb 2) and
  Fb 12 under-splits VoxConverse (2.67). Fb 5-8 is the flat region. loopP 0.3-0.7 is flat; 0.9
  is slightly worse. Spans are seconds long, not the 0.25 s steps the recipe's 0.99 assumes.
- LDA 96 was 0.19 points better than 128 at the preset point, which is within noise; 128 is kept.
  Smoothing 3-10 makes no difference.
- **Dense windows hurt on every grid point we compared.** The best weighted dev DER was 7.48 with
  windows against 6.89 without. CAM++ centre-pads a 1.5 s window to its 3 s input, so a window
  embedding is noisier than the span embedding it replaces.
- The grid median (9.35) is close to merge-only. VBx is sensitive to its settings on these short
  recordings.

## Test (untouched T6 sets, one run)

Bundled PLDA, committed preset, no overrides (`echo-proto-t10`, raw JSON
`t10/results/final/`):

| Set | Mode | DER % | Miss % | FA % | Conf % | Est / true spk | Exact |
|---|---|---|---|---|---|---|---|
| `mls_es` | merge-only | **7.31** | 2.94 | 0.70 | 3.67 | 4.15 / 2.80 | 3/20 |
| `mls_es` | VBx | 10.91 | 2.94 | 0.70 | 7.27 | **3.45** / 2.80 | **10/20** |
| `voxconverse` | merge-only | **5.56** | 2.53 | 0.92 | 2.11 | 4.67 / 3.33 | 2/12 |
| `voxconverse` | VBx | 6.10 | 2.66 | 0.87 | 2.57 | 3.08 / 3.33 | 5/12 |

Weighted test DER: merge-only **6.73**, VBx **9.31**.

Per file, VBx is better or equal on 13 of the 20 Spanish conversations. Four of them still fall
apart, with DER going from 3-9 % to 24-36 %: conv03, conv10, conv13 (7 speakers against 3 true)
and conv19. The cause is the per-recording two-Gaussian AHC threshold. On a 3-5 minute
conversation with 100-200 entries it sometimes lands so that VBx starts from merged or shredded
speakers, and VBx does not recover. Dev had no such file, so the dev gain did not carry over to
test.

### Q4 outcome

The criterion is: weighted test DER at least 0.5 points below merge-only (at most 6.23), **and**
Spanish estimated speakers at most 4.15.

- Speakers: 3.45 ≤ 4.15, **met**.
- DER: 9.31 against the 6.23 required. **Missed by 3.08 points**: VBx is 2.58 points worse than
  merge-only.

**The default stays `MergeOnly`** for every family. `Resegment` (VBx) stays available behind
`ECHO_DIAR_REFINE=reseg` (debug builds) and `bench der --refine-mode resegment`.

## Long session and cost

Apple M1 Pro, one bench at a time, release build `echo-proto-t10`, raw JSON in
`t10/results/cost/`.

**Live cost (dev, `mls_es_dev`, 89.9 min of audio).** The pipeline real-time factor covers the
VAD, the segmenter and the embedder, with no ASR:

| Mode | Pipeline RTF | Refine at stop (max / median per file) |
|---|---|---|
| merge-only | 0.0395 | 0 ms |
| VBx, no windows (preset) | 0.0393 | 16 / 5 ms |
| VBx + dense windows | 0.0605 (+54 %) | 26 / 8 ms |

Without windows, VBx adds no live cost: it only reads the log the merge-only refine already
keeps.

**Long session (3.02 h).** The 20 `mls_es_dev` conversations were concatenated twice with 2 s
gaps: 20 distinct readers, 1 189 chunks. VBx ran 21 times on the same log (the main refine plus
a 20-repeat grid of the preset):

| Mode | DER % | Est / true spk | Refine at stop | Pipeline RTF |
|---|---|---|---|---|
| merge-only | 55.14 | 8 / 20 | 1 ms | 0.0390 |
| VBx (preset) | **6.47** | 20 / 20 | 994 ms (max of 21 runs: 994 ms) | 0.0408 |
| VBx + dense windows | **5.01** | 20 / 20 | 1 706 ms (max 1 706 ms) | 0.0634 |

The refine p95 is at most 1.0 s (1.7 s with windows). That is well inside the ADR target of
p95 ≤ 5 s and the 20 s hard timeout. The online cap of 8 speakers is what breaks merge-only here:
it can only merge. VBx can create speakers, so it recovers all 20. This stream is synthetic, and
20 speakers in one meeting is an extreme case.

**Memory.** Process peak RSS is not informative here: the bench decodes the whole 3 h file into
RAM (about 0.7 GB), and the RSS reported by `time -l` varied by ±200 MB between identical runs.
The refine's own memory is measured by counting allocations in
`crates/echo-diarize/tests/resegment_memory.rs` (ignored; run in release). The log is filled to
its caps with dense windows on (16 448 chunks of 4.5 s; the windows are thinned below their cap):

| Measure | Value |
|---|---|
| Log held at stop | 18.9 MB |
| Stop-time transient (peak allocated above the log) | **30.5 MB** (Q3 target: about 35 MB) |
| Refine time | 0.61-0.63 s |
| Merge-only transient at the 16 384-entry cap | 1 074 MB before T10, about 0 now (`tests/merge_only_memory.rs`) |

The transient comes from the LDA-space vectors and the AHC matrix (2 048 representatives,
8.4 MB), then from the VBx statistics, which are scaled in place.

## Findings

1. **VBx fixes the speaker count but not reliably the DER.** On test it cut the Spanish
   over-count from +1.35 to +0.65 speakers and more than tripled the exact counts. A few
   recordings, though, start from a bad initialisation and end with large confusion.
2. **The initialisation is the weak point.** The VBx recipe's per-recording threshold assumes
   long recordings with dense 0.25 s frames. Ours have about 100-600 variable-length spans. Next
   steps to try, on dev first:
   - initialise VBx from the online speakers, so VBx only refines and can never start worse
     than the online result;
   - use a fixed AHC cut in the LDA space instead of the two-Gaussian threshold;
   - accept a plan only if its VBx ELBO beats the online labelling's (fail-safe to the online
     result).
3. **Long sessions are where VBx is strongest.** In a 3 h stream the online cap of 8 speakers is
   the bottleneck: merge-only cannot add speakers and VBx can (see the cost table).
4. **Dense windows are not worth their cost on short recordings.** With the CAM++ input length
   they raised dev DER (8.98 against 7.35 at the preset) and add 54 % to the pipeline time. On
   the 3 h stream they helped (5.01 against 6.47), so they stay available and tested, but off.
5. Recipe defaults (Fb 17, loopP 0.99) are wrong for this setting and collapse recordings to one
   or two speakers. The preset must be calibrated per embedder, like the online thresholds.

## T10b: initialisation cut in the LDA space, second look at test

Date: 2026-10-13, commits `4f24b81..3de6f01`. Raw JSON in the session scratchpad (`t10b/results/`).

**Question.** The T10 review suggested that the VBx initialisation cut was calibrated as a cosine
cut on raw embeddings but applied to cosine similarities in the PLDA's LDA space, and that this
caused the test files that fell apart.

**What the code did.** On the production path the hypothesis does not hold: the two-Gaussian
calibration ran on the pairwise LDA-space similarities, the same ones the AHC cuts. Two inputs
were in the wrong space, though. The fixed cut and the calibration fallback came from the
raw-embedding `resegment_threshold` (0.50), and `bench der --refine-threshold` overrode the VBx
cut with a raw-space value. T10b moves every cut into `VbxConfig::init` (`Calibrated { offset,
fallback }` or `Fixed`), all LDA-space similarities, with an LDA-space fallback of 0.45. On the
dev sets the calibration never fell back, so the preset's output is unchanged (dev 3.59 / 14.88
before and after).

**Dev evidence (dev sets only).** Per-recording calibrated cuts (with the +0.15 offset), from a
`debug` log of the cut:

| Dev set | Cut mean | SD | Min | Max |
|---|---|---|---|---|
| `mls_es_dev` (20) | 0.471 | 0.036 | 0.429 | 0.559 |
| `voxconverse_dev` (12) | 0.572 | 0.038 | 0.493 | 0.626 |

The calibration adapts by about 0.1 between the two sets and varies little within each. Grids
(105 settings) compared it with fixed LDA-space cuts and with starting VBx from the online
speakers:

| Init (Fa 0.5, Fb 5, loopP 0.5 unless noted) | ES dev | Vox dev | Weighted | ES est / true | Worst ES file |
|---|---|---|---|---|---|
| Calibrated +0.20 | 3.59 | 13.53 | 6.90 | 3.45 / 3.45 | 8.5 |
| **Calibrated +0.15 (preset)** | **3.59** | **14.88** | **7.35** | 3.50 / 3.45 | 8.5 |
| Calibrated +0.10 | 3.59 | 17.02 | 8.06 | 3.50 / 3.45 | 8.5 |
| Calibrated +0.05 | 4.65 | 15.41 | 8.24 | 3.45 / 3.45 | 29.4 |
| Fixed 0.45 (best fixed) | 3.59 | 15.41 | 7.53 | 3.50 / 3.45 | 8.5 |
| Fixed 0.40 | 3.59 | 17.02 | 8.01 | 3.50 / 3.45 | 8.5 |
| Fixed 0.50 | 4.05 | 17.03 | 8.38 | 3.50 / 3.45 | 11.3 |
| Fixed 0.30 | 4.62 | 19.80 | 9.68 | 3.45 / 3.45 | 29.4 |
| Fixed 0.25 | 6.32 | 30.01 | 14.22 | 3.40 / 3.45 | 38.5 |
| Online speakers, best (Fb 2, Fa 0.3) | 6.34 | 14.87 | 9.18 | 3.65 / 3.45 | 38.9 |

- The fixed cuts have a narrower flat region (0.40-0.45) and a cliff below 0.30. No fixed cut
  beat the calibrated one, and both have the same worst Spanish file. On VoxConverse dev the
  instability is per file for both: single recordings jump between about 13-20 % and 41 % DER
  from one setting to its neighbour (calibrated +0.15 against +0.20, fixed 0.45 against the
  calibrated cut).
- Starting from the online speakers is worse (best weighted 9.18): when the online clustering
  merged two voices, VBx cannot split them again.
- A guard that keeps the merge-only result when VBx finds more speakers never fired on dev, so
  there is no dev evidence for it and it was not added.

The dev choice is therefore the T10 preset (calibrated +0.15, Fa 0.5, Fb 5, loopP 0.5); Fa, Fb
and loopP were not re-gridded because the cut they were calibrated with did not change.

**Test (second look at the T6 test sets, one run).** This is the second time these test sets
were scored with VBx (the first was T10). No setting was chosen from either test run. Release
build at `3de6f01`, committed preset, no overrides:

| Set | Mode | DER % | Miss % | FA % | Conf % | Est / true spk | Exact |
|---|---|---|---|---|---|---|---|
| `mls_es` | merge-only | **7.31** | 2.94 | 0.70 | 3.67 | 4.15 / 2.80 | 3/20 |
| `mls_es` | VBx | 10.91 | 2.94 | 0.70 | 7.27 | **3.45** / 2.80 | **10/20** |
| `voxconverse` | merge-only | **5.56** | 2.53 | 0.92 | 2.11 | 4.67 / 3.33 | 2/12 |
| `voxconverse` | VBx | 6.10 | 2.66 | 0.87 | 2.57 | 3.08 / 3.33 | 5/12 |

Weighted test DER: merge-only **6.73**, VBx **9.31**, identical to T10 for every file (DER and
speaker count), so the new fallback value changed no test result.

**Q4 (T10b).** Speakers 3.45 ≤ 4.15, met. DER 9.31 against at most 6.23, **missed by 3.08
points**. The default stays `MergeOnly` for every family.

**Conclusion.** The space mismatch was real only on the fallback and bench paths, which the
production preset never used, so fixing it could not explain the test failures. The bad test
files come from the AHC initialisation on 100-200 entries landing on merged or shredded seeds
that VBx does not recover from, and the dev sets do not contain such a case: on dev the worst
Spanish file is 8.5 % for both calibrated and fixed cuts. A follow-up needs either more varied
dev data or a selection rule that dev can validate, for example running VBx from several
initialisations and keeping the best ELBO.

## Reproduce

```
# PLDA: embeddings with the app's adapter, then the fit (numpy + scipy venv, python -I)
echo-proto bench embed-dump --list list.txt --embedder <campplus_zh_en_common_advanced.onnx> \
  --embedder-id embedder-campplus-multi --out all.bin
python -I scripts/fit-plda.py --lda-dim 128 --out plda.bin all.bin

# Calibration grid on a dev set (one VBx spec per line, e.g. init=cal:0.15,fa=0.5,fb=5,loop=0.5;
# init=<cut> is a fixed cut; every cut is an LDA-space cosine similarity)
ECHO_LOG=warn echo-proto bench der --manifest <set>/manifest.txt --embedder <...> \
  --embedder-id embedder-campplus-multi --segmenter <...> --vad <...> \
  --refine-mode resegment [--plda plda.bin] [--dense-windows] --vbx-grid grid.txt --json
```
