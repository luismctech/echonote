# v0.6.0 model assets

Two model files that EchoNote builds itself are hosted as assets of the
GitHub release `v0.6.0` of `luismctech/echonote`. The in-app catalog
(`src-tauri/src/commands/models.rs`) downloads them from:

```
https://github.com/luismctech/echonote/releases/download/v0.6.0/<file>
```

**These downloads fail until release `v0.6.0` is published with both files
attached.** Publish the assets before (or together with) the app build that
ships this catalog.

## Assets

| `silero_vad_v6_2.onnx` | `76d1667a4962c0eac51c41ba440b188bb4726293f356ec9bec780f7d1a6f08b8` | 1,557,280 | [snakers4/silero-vad](https://github.com/snakers4/silero-vad) v6.2.3, commit `5cd7945676eb32225748052e2e6a0580e4686a08`, `src/silero_vad/data/silero_vad_op18_ifless.onnx` (SHA-256 `7671cd04b004e9076da0d4a7b1a5aec36adf161c39230c1cb94a4fd5db6bbd28`, 2,845,718 B), 16 kHz branch inlined by `scripts/inline-silero-vad.py` | MIT, © Silero Team |
| `pyannote_segmentation_3_tract.onnx` | `f7e21b2898bf772836ac5784b91663d7cb869f8899e5c501e42ad747fb5a7b78` | 5,988,123 | [pyannote/segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0) via the sherpa-onnx ONNX export [csukuangfj/sherpa-onnx-pyannote-segmentation-3-0](https://huggingface.co/csukuangfj/sherpa-onnx-pyannote-segmentation-3-0) `model.onnx` (SHA-256 `220ad67ca923bef2fa91f2390c786097bf305bceb5e261d4af67b38e938e1079`, 5,992,913 B), `InstanceNormalization` decomposed and the no-op `If` folded by `scripts/patch-pyannote-segmenter.py` | MIT (pyannote/segmentation-3.0 model card) |

Why EchoNote hosts them: `tract-onnx` 0.22 cannot run either upstream file
(the Silero file dispatches through an ONNX `If`; the segmenter's
`InstanceNormalization` fails analysis). Both rewrites are numerically
equivalent for the inputs EchoNote uses (16 kHz audio; `[1, 1, 80000]`
segmenter windows, max abs diff vs the original 1.2e-5 with onnxruntime).

Not hosted here:

- The embedders (`embedder-campplus-multi`, `embedder-camplusplus`,
  `embedder-eres2net`) still download unmodified from
  `huggingface.co/csukuangfj/speaker-embedding-models`; their catalog SHA-256
  values match the files in use.
- The PLDA model of the multilingual CAM++ is bundled in the binary
  (`include_bytes!`).

## Regenerate

Both scripts are deterministic: the commands below reproduce the hashes above
(checked with onnx 1.23.2, onnxruntime 1.31.0, numpy 2.5.4).

```bash
python3 -m venv .venv-assets && . .venv-assets/bin/activate
pip install onnx onnxruntime numpy

# Silero VAD v6.2.3
curl -L -o silero_vad_op18_ifless.onnx \
  https://github.com/snakers4/silero-vad/raw/5cd7945676eb32225748052e2e6a0580e4686a08/src/silero_vad/data/silero_vad_op18_ifless.onnx
python3 scripts/inline-silero-vad.py \
  --input silero_vad_op18_ifless.onnx --output silero_vad_v6_2.onnx

# pyannote segmentation 3.0 (needs onnxruntime for the equivalence check)
curl -L -o pyannote_segmentation_3.onnx \
  https://huggingface.co/csukuangfj/sherpa-onnx-pyannote-segmentation-3-0/resolve/main/model.onnx
python3 scripts/patch-pyannote-segmenter.py \
  pyannote_segmentation_3.onnx pyannote_segmentation_3_tract.onnx

shasum -a 256 silero_vad_v6_2.onnx pyannote_segmentation_3_tract.onnx
```

Verify both hashes and both inputs' hashes against the table before upload.

## Upload (manual)

Run from the directory holding the two files, after the `v0.6.0` release
exists (the release workflow creates it as a draft on tag push):

```bash
gh release upload v0.6.0 \
  silero_vad_v6_2.onnx \
  pyannote_segmentation_3_tract.onnx \
  --repo luismctech/echonote
```

Then publish the draft and check one download:

```bash
curl -L https://github.com/luismctech/echonote/releases/download/v0.6.0/silero_vad_v6_2.onnx \
  | shasum -a 256
```

## Behaviour for existing installs

- **VAD.** The file keeps its on-disk name (`models/vad/silero_vad.onnx`), so
  the catalog reports it installed only when it is the pinned v6.2 build (size
  and SHA-256). The v5 file of release v0.2.1 therefore appears as not
  installed and the Models panel offers the download. Until the user updates,
  the shell keeps loading the old file with a warning (the v0.2.1 file accepts
  the 576-sample input); if an old file fails to load, recording continues on
  the RMS gate instead of failing. A finished VAD download drops the cached
  model so the next session uses the new file.
- **Segmenter.** The catalog now installs
  `models/segmenter/pyannote_segmentation_3_tract.onnx`. Installs that only
  have the upstream `pyannote_segmentation_3.onnx` (which never loaded in
  tract) see the segmenter as not installed. Once the tract file is present,
  the next session uses it without an app restart.
